## 2026-09-24
* **Fix**: every string the raw C wrote into an untracked var leaked (32 bytes per 2-byte reply; `RETURN_CCTOR`/`CCTORW` duplicate it and nothing drops the local). Ten methods fixed the same way: `ftdiNew`, `ftdiGetLibraryVersion`, `ftdiUSBGetStrings`, `ftdiUSBGetStrings2`, `ftdiReadData`, `ftdiTransferReadDone`, `ftdiEepromGetStrings`, `ftdiGetEepromBuf`, `setFT232HCbus`, `ftdiGetErrorString`. Committed C patched in those methods only. FT232H: heap growth over 5000 blocking and 5000 submitted reads went from 160000 bytes to under 16 KiB (`microscrap/mpsse` `FtdiReplyLeakFeatureTest`), on Homebrew NTS, ZTS and Herd. Trap rewritten: [Zephir and raw-C vars](/traps/zephir-narrows-raw-c-vars.md).
* **Fix**: `ftdiTransferReadDone` always returned `false`. Zephir narrowed `out` to `zend_bool` (it was assigned `false` in Zephir), so the C block wrote a zval into one byte of stack. `out` now gets every value from C. Committed `ext/ftdi/ftdi.zep.c` patched in that one method only (a full regenerate on this Zephir switches every class-entry lookup to `zephir_get_internal_ce`, not shipped). Throwaway `phpize && make` of committed `ext/` passes `scripts/smoke.php`; reinstalled into Homebrew 8.4 NTS and ZTS and Herd 8.4. FT232H + LIS3DH: submitted read returns `00000033` (WHO_AM_I after three ACKs). New trap: [Zephir narrows raw-C vars](/traps/zephir-narrows-raw-c-vars.md).

## 2026-09-23
* **Update**: 0.9.0 line. New `Ftdi\FTDI` bindings: `ftdiGetPollfds`, `ftdiPollfdsHandleTimeouts`, `ftdiGetNextTimeout`, `ftdiHandleEventsTimeout`, `ftdiTransferCompleted`, `ftdiTransferReadDone` (1:1 libusb event pump over `ftdi_context->usb_ctx`). `ftdiWriteDataSubmit` now copies its data; `ftdiTransferDataDone` / `ftdiTransferReadDone` / `ftdiTransferDataCancel` free the extension-owned buffer and zero the control (fixes the read-submit leak and the in-flight write referencing a PHP string). `ext/` regenerated on a copy; stubs to `ide/0.9.0/`, `ide/0.2.0` removed. Installed into Herd 8.4, Homebrew 8.4 NTS and ZTS. `scripts/smoke.php` is the hardware-free check.
* **Build**: `clang/config.m4` (and the committed `ext/config.m4`) now adds `pkg-config libusb-1.0` cflags and libs. libftdi 1.5's `ftdi.h` does not declare the libusb pollfd API, and libftdi's include path does not reach `<libusb.h>`. A Zephir gotcha from this cut: a local named `tcHandle`, assigned from `tc->handle` and then written back to `tc->…`, fails `zephir generate` with "Cannot use variable: int to assign property value"; naming it `handle` works.
* **Finding**: on macOS with libusb 1.0.29, `ftdiGetPollfds` returns **one** fd, not `[]` as the plan assumed. `[]` means libusb returned `NULL` or the context is dead.
* **Finding**: `zephir stubs` writes the stock kernel back over the `clang/kernel/` overlays, and a whole-directory `rsync` of `ext/` subdirectories drags in `*.lo`, `*.dep` and `.libs/`. Both are recorded in the [regenerate playbook](/playbooks/regenerate-ext.md). The committed `ext/kernel/{file,main,require}.c` were kept equal to `clang/kernel/`. A throwaway `phpize && make` of the committed `ext/` builds and passes the smoke.
* **Hardware**: FT232H (0403:6014) smoke on Herd 8.4 — async write via the event pump returned `3`, then `handle` and `bufHandle` were `0`; the two-byte read did not complete within 0.5 s and was cancelled cleanly. Still owed: `ftdiTransferReadDone` on a read served from libftdi's internal readbuffer (`transfer == NULL`).
